# AI Customer Support Agent & RAG Evaluation Pipeline

An end-to-end AI support agent for `@AmazonHelp` built on Twitter Customer Support data (`twcs.csv`).

## 🎯 Architecture & Capabilities

1. **Intent Classification:** Identifies categories like Order Tracking, Refunds, Account Issues, and General Inquiries.
2. **Grounded Reply Generation:** Uses FAISS vector search (`all-MiniLM-L6-v2`) and `google/flan-t5-base` to draft responses.
3. **Escalation Engine:** Automatically routes complex queries (payment disputes, account verification) to human agents.

## 📊 Benchmark Results

Evaluated on a **Golden Evaluation Set of 150 queries**:

| Model / Pipeline | ROUGE-1 Score | Description |
| :--- | :--- | :--- |
| **Simple LLM Baseline** | `0.1009` | Flan-T5 prompt without retrieval context |
| **Trivial Baseline** | `0.1246` | Static prediction of most frequent support template |
| **Proposed RAG Agent** | **`0.1464`** | Vector retrieval + context-grounded Flan-T5 |

## 🔍 Mandatory Analysis

### What is Misleading About My Headline Number?
* ROUGE metric measures lexical unigram overlap, penalizing valid responses that use different phrasing.
* Twitter support logs contain repetitive template phrases ("DM us your order ID") which can artificially inflate unigram overlap even on non-specific replies.

### Failure Modes (Top 5)
1. **Vague Queries:** Short tweets lacking order IDs.
2. **Multi-Turn Context Loss:** Single QA-pair evaluation loses thread history.
3. **Template Over-reliance:** RAG retrieval sometimes fetches generic responses.
4. **Entity Errors:** Placeholder links generated by smaller models.
5. **Intent Overlap:** Queries spanning both refunds and delivery delays.

## 📝 Decision Log
1. **Model:** Used `google/flan-t5-base` for lightweight instruction following.
2. **Embeddings:** `all-MiniLM-L6-v2` for fast, efficient vector search.
3. **Vector Index:** `FAISS FlatL2` for local, sub-millisecond similarity search.
4. **Evaluation:** ROUGE metrics combined with multi-baseline comparisons.
